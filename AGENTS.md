# Project instructions

- Address the project owner as “bro” naturally. Keep communication casual, friendly, and concise.
- Before implementing a phase, read its prompt, the previous phase handoff, and the shared rules/audit in `implementation-prompts/` when relevant. Work on one numbered phase at a time.
- Treat `PHASE_PROGRESS.md` as the project’s authoritative phase-status tracker. Count a phase as complete only when its handoff says it is verified; preserve any caveats recorded there.
- **Required progress update:** Whenever project work changes any code, assets, configuration, tests, documentation, or other project files, update `PHASE_PROGRESS.md` in the same change set before finishing. Update phase status/evidence when it changes. If the work does not change phase completion, add a concise entry to the change log so every project change is recorded. This rule is mandatory for every implementation task, including work that spans multiple turns. Read-only inspection does not require a tracker update.
- Keep the tracker’s completed count consistent with phases marked `VERIFIED`, and its remaining count consistent with the 24-phase roadmap in `implementation-prompts/README.md`.
- Do not mark planned work complete. Record verification scope and any unrun manual or visual checks accurately.
